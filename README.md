# Local Task Manager Backend

A modular FastAPI backend backed by Python's built-in `sqlite3` module, with an Ollama agent, image-based timetable extraction, and a Markdown “Second Brain” notes store. The database is named `productivity.db` and is created in this project directory by default. By default, prompts and task data go only to the local Ollama endpoint at `localhost`; setting `OLLAMA_URL` to another host is an explicit configuration choice.

## Run locally

Python 3.10 or newer is recommended. SQLite is included with Python.

```bash
cd task_management_backend
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python init_db.py
uvicorn app.main:app --reload
```

The API and UI are available at `http://localhost:8000/`; interactive OpenAPI docs are at `http://localhost:8000/docs`. FastAPI serves the `frontend/` directory at the same origin so the browser can call the API without extra CORS configuration. The API initializes the database on startup as well, so running `init_db.py` first is optional.

To use a different database file, set `TASKS_DB_PATH` before running the script or server.

## Task endpoints

### `GET /tasks`

Returns all tasks in creation order. Optionally filter by status:

```http
GET /tasks?status=inbox
```

### `POST /tasks`

Creates a task with its status set to `inbox` and no scheduled start. `id` and `created_at` are generated by SQLite.

```json
{
  "title": "Prepare project update",
  "category": "Work",
  "estimated_minutes": 30
}
```

Returns the created task with HTTP `201 Created`.

### `PUT /tasks/{task_id}`

Updates both `status` and `scheduled_start`. Include both fields; use an ISO 8601 datetime to schedule the task or `null` to clear its scheduled start.

```json
{
  "status": "scheduled",
  "scheduled_start": "2026-10-03T09:30:00"
}
```

A nonexistent task returns HTTP `404 Not Found`.

The same task endpoints are also available under `/api/tasks` as a compatibility alias. The alias is used by the UI's drag-and-drop scheduler; it is intentionally omitted from the generated OpenAPI schema to avoid duplicate documentation.

### `PATCH /tasks/{task_id}`

Partially edits a task's title, category, and/or estimate. For example:

```json
{
  "title": "Review the revised project brief",
  "estimated_minutes": 45
}
```

### `DELETE /tasks/{task_id}`

Permanently deletes a task and returns HTTP `204 No Content`. Missing task ids return `404`.

## Timetable image extraction

### `POST /api/extract-timetable`

Accepts a multipart form upload with an image field named `file`. The backend Base64-encodes the image, sends it to the configured local Ollama vision model, validates the returned JSON array, and saves each event in SQLite with status `scheduled` and category `Timetable`. It returns the created task records with HTTP `201 Created`; if the image contains no events, the response is an empty array.

```bash
curl -X POST http://localhost:8000/api/extract-timetable  \
  -F "file=@weekly-timetable.png;type=image/png"
```

The model is instructed with this prompt:

> Extract all scheduled events, classes, or meetings from this timetable image. Return the result strictly as a JSON array where each object has a 'title', 'estimated_minutes', and 'scheduled_start' (in ISO 8601 format).

For example, the response is an array of normal task records:

```json
[
  {
    "id": 21,
    "title": "Project planning",
    "category": "Timetable",
    "estimated_minutes": 45,
    "status": "scheduled",
    "scheduled_start": "2026-10-14T09:30:00",
    "created_at": "2026-10-13T12:00:00"
  }
]
```

Ollama must be running with an image-capable model available. The default vision model is `llava`; download it with `ollama pull llava`. Configure it with `OLLAMA_VISION_MODEL`. The endpoint uses `OLLAMA_URL` (default `http://localhost:11434/api/chat`) and `OLLAMA_TIMEOUT_SECONDS` (default `120`), shared with the chat agent. Uploads must have an `image/*` content type and are limited to 20 MiB by default; set `MAX_TIMETABLE_IMAGE_BYTES` to change that limit. Empty uploads return `400`, unsupported media types return `415`, oversized uploads return `413`, and Ollama/extraction errors (including unreadable image data) return `502`.


## Second Brain notes

Notes are Markdown text with a comma-separated `tags` string. SQLite creates `id` and `created_at`; omitted tags default to an empty string. The `task_notes` junction table has a unique `(task_id, note_id)` primary key and foreign keys with `ON DELETE CASCADE`, so either side can be associated with multiple records and duplicate links are prevented.

### `POST /notes`

Create a note. Markdown content is preserved; tags are normalized as comma-separated values.

```json
{
  "content": "## Useful idea\n\nA note in Markdown.",
  "tags": "research, product"
}
```

Returns the created note with HTTP `201 Created`.

### `GET /notes` and `GET /notes/{note_id}`

List notes (newest first) or fetch a single note. A missing note returns `404`.

### `PUT /tasks/{task_id}/notes/{note_id}`

Idempotently link an existing note to an existing task. The response contains `task_id` and `note_id`; a missing task or note returns `404`.

### `GET /tasks/{task_id}/context`

Return the task details and all its linked notes. The `notes` array is empty when there are no links; a missing task returns `404`.

```json
{
  "task": {
    "id": 17,
    "title": "Prepare literature review",
    "category": "Research",
    "estimated_minutes": 30,
    "status": "inbox",
    "scheduled_start": null,
    "created_at": "2026-10-08T10:30:00"
  },
  "notes": [
    {
      "id": 4,
      "content": "## Useful idea\n\nA note in Markdown.",
      "tags": "research, product",
      "created_at": "2026-10-08T10:32:00"
    }
  ]
}
```

### `GET /notes/{note_id}/tasks`

Return the tasks linked to a note (the reverse lookup for the many-to-many relationship).

The same notes and context routes are also available under `/api/notes` and `/api/tasks` as hidden compatibility aliases. Run the integration tests with `python -m unittest discover -s tests -v`.

## Local Ollama agent

Start Ollama and make a tool-capable model available. The default model is `llama3.1`:

```bash
ollama pull llama3.1
```

The backend sends non-streaming chat requests to `http://localhost:11434/api/chat` by default. Configure the model or endpoint with `OLLAMA_MODEL` and `OLLAMA_URL` if needed. `OLLAMA_TIMEOUT_SECONDS` controls the HTTP timeout (default `120`); `AGENT_MAX_TOOL_ROUNDS` limits tool-call cycles (default `8`).

### `POST /api/agent`

Request:

```json
{
  "prompt": "Find a free 30-minute slot tomorrow."
}
```

The response contains the assistant's final text and a record of each tool call/result:

```json
{
  "response": "There is a free slot tomorrow from 09:00 to 10:00.",
  "tool_calls": [
    {
      "name": "get_available_time_slots",
      "arguments": {"date": "2026-10-04", "estimated_minutes": 30},
      "result": {
        "date": "2026-10-04",
        "window_start": "09:00",
        "window_end": "17:00",
        "required_minutes": 30,
        "available_slots": [
          {"start": "2026-10-04T09:00", "end": "2026-10-04T10:00", "available_minutes": 60}
        ]
      }
    }
  ]
}
```

The agent passes four function schemas to Ollama and dispatches only these allowlisted functions:

- `get_available_time_slots`: reads scheduled tasks and returns free contiguous windows. Defaults to 09:00–17:00 local wall-clock time; set `TASKS_WORKDAY_START` / `TASKS_WORKDAY_END` to change these defaults, or provide `window_start` / `window_end` in the tool call.
- `create_task`: inserts a new task in the inbox.
- `fetch_tasks_by_status`: selects tasks by exact status.
- `reschedule_task`: changes a task's scheduled start and sets status to `scheduled`. It checks for overlaps with other active scheduled tasks; completed/cancelled tasks are not treated as blockers.

The service appends Ollama's assistant tool-call message, executes each SQLite operation, appends the result as a `tool` message, and calls Ollama again for a user-facing confirmation. Tool arguments are parsed and validated, unknown tools are rejected, and no model-generated code is executed. If Ollama is unreachable or returns an invalid request/response, `/api/agent` responds with HTTP `502`.

## Static UI layout

`frontend/index.html` provides the dark-mode 30% inbox / 70% schedule layout and `frontend/app.js` connects it to the API. The UI supports task completion, editing details with `PATCH`, confirmed deletion, and quick-entry category/estimate fields. AI Assist posts to `POST /api/agent`; after it completes, the app refreshes both the inbox and schedule. Scheduled tasks are rendered for the selected local day on the 8:00 AM–8:00 PM timeline. Quick-entry defaults are `General` and 30 minutes, both editable before saving.

Use the **Focus** button to hide the inbox and expand the schedule; click it again to restore the two-pane layout. Inbox cards can be dragged onto the schedule. The drop indicator previews a start time snapped to 15-minute increments, and the drop persists the task as scheduled with `PUT /api/tasks/{task_id}`. The chosen start is kept within the workday based on the task's estimate. If the save fails, the optimistic schedule change is rolled back and an error is shown.

The calendar has **Day** and **Month** views. The month grid shows scheduled items by date; use the arrows to move by a day or month, and select a date to open its day timeline. The floating **AI Chat** panel toggles from the bottom-right corner and sends messages to `/api/agent`; message history remains in the open page session. Click a task card or title to open the sliding **Second Brain** drawer. It shows linked notes and lets you save Markdown content with comma-separated `#tags` to that task.
